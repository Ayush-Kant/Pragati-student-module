Problem Definition

THE CHALLENGE

Fragmented Coordination

Placement processes are spread across emails, spreadsheets, and physical notices, causing delays and data inconsistency.

Manual Tracking

Student progress, applications, interviews, and offers tracked manually — error-prone and lacking real-time visibility.

No Standardized Assessment

Lack of an integrated platform for MCQ and coding assessments to measure candidate readiness consistently.

Inefficient Training

Training coordination, mentor assignment, and progress tracking require significant manual administrative effort.

Core Problem: No unified digital platform exists to connect students, recruiters, colleges, mentors, and admins across the entire placement lifecycle.

Introduction & Scope

PROJECT OVERVIEW

Pragati (meaning "Progress" in Sanskrit) is an end-to-end campus placement ecosystem connecting five user roles on a single platform. It automates student onboarding, training, assessment, recruitment drives, interviews, and offer management.

Built with React 19, Node.js/Express 5, PostgreSQL, JWT auth, and RESTful API architecture.

Scope of the System

  • Student Module — Profiles, courses, assessments, coding challenges, interviews, offers
  • Company Module — Drives, candidates, assessments, interviews, offers, training
  • College Module — Departments, students, nominations, reports, announcements
  • Mentor Module — Courses, question bank, quizzes, live sessions, analytics
  • Admin Module — User management, approvals, disputes, notifications, audit

Requirement Specification

FUNCTIONAL & NON-FUNCTIONAL REQUIREMENTS

Functional Requirements

  • JWT-based authentication with role-based access
  • Student profile & placement readiness tracking
  • Recruitment drive CRUD with eligibility criteria
  • Assessment engine: MCQ, multi-select, T/F, fill-blank, match
  • Coding challenge engine with test case validation
  • Interview scheduling and offer management
  • Training coordination with mentor assignment
  • Reporting and analytics dashboards

Non-Functional Requirements

  • Security: JWT auth, bcrypt hashing, role-based access
  • Scalability: Horizontal scaling support
  • Performance: API response < 500ms
  • Responsiveness: Desktop, tablet, mobile support
  • Reliability: 99.5% uptime, error handling, logging
  • Maintainability: Modular architecture, consistent standards
  • Data Integrity: Input validation (Joi/Zod), constraints

Methodology

DEVELOPMENT APPROACH & ARCHITECTURE

Agile Development Phases

  • Weeks 1-2: Requirements gathering & analysis
  • Weeks 3-4: System design & architecture
  • Weeks 5-10: Backend development (API + DB)
  • Weeks 8-14: Frontend development (React)
  • Weeks 12-16: Integration & testing
  • Weeks 15-18: Deployment & documentation

System Architecture

Frontend: React 19 + Vite + Tailwind CSS + TanStack Query

Backend: Node.js + Express 5 (Routes → Middleware → Controllers → Services → DB)

Database: PostgreSQL (50+ tables, normalized schema)

Auth: JWT tokens with role-based middleware

Validation: Joi (backend) + Zod (frontend)

Email: Resend API for notifications

Client-Server Architecture: SPA (React) ↔ REST API (Express) ↔ PostgreSQL
